rage – Encrypt & Decrypt Reference

How to correctly encrypt and decrypt files with a passphrase on Windows and Linux

1. Basic Commands

Both Encrypt a file with a passphrase

rage --passphrase -o encrypted.age original.zip
# or short form:
rage -p -o encrypted.age original.zip

You will be prompted to type a passphrase (and usually confirm it). Leave it empty if you want rage to auto-generate a strong passphrase for you.

Both Decrypt a file

rage --decrypt -o restored.zip encrypted.age
# or short form:
rage -d -o restored.zip encrypted.age

You will be asked for the same passphrase you used when encrypting.

2. Why you should always use -o (especially on Windows)

Windows can silently corrupt binary files when you use redirection (>)

The age format used by rage is binary. When you write: 
rage --decrypt encrypted.age > restored.zip
the Windows shell (especially PowerShell, and sometimes CMD) may treat the binary stream as text. This can result in:
  • Conversion to UTF-16 (null bytes inserted between characters)
  • Unwanted CRLF line-ending changes
  • A completely broken / “not a valid ZIP” file

This is a well-known issue with the original age tool and with rage on Windows. The tool itself works correctly — the shell is the problem.

Best practice on both platforms
Always write the output file with the -o / --output flag. This lets rage write the file directly and completely avoids shell redirection problems.

3. Recommended commands (safe on Windows & Linux)

Action Command
Encrypt rage -p -o secret.age myfile.zip
Decrypt rage -d -o myfile.zip secret.age
Encrypt (armored / text) rage -p -a -o secret.age myfile.zip
Decrypt armored file rage -d -o myfile.zip secret.age

4. Platform notes

Windows

  • Open a normal Command Prompt (cmd.exe) or Windows Terminal.
  • Do not just double-click a .bat file if you need to type a passphrase — the window may close too quickly or the prompt may behave strangely.
  • Always prefer the -o flag. Avoid > redirection for binary encrypted files.
  • Make sure rage.exe is in your PATH (or use the full path to the executable).

Linux / macOS

  • Redirection (>) usually works fine because Unix shells treat pipes and redirection as raw byte streams.
  • Still recommended to use -o for consistency and clarity.
  • Example that works on Linux: 
    rage -p -o secret.age myfile.zip
rage -d secret.age > myfile.zip

5. Quick checklist when something goes wrong

  1. Did you use -o on both encrypt and decrypt?
  2. Is the passphrase exactly the same (including case and no extra spaces)?
  3. Does the encrypted file (.age or .enc) exist and is it larger than the original?
  4. After decrypt, does the restored file have the exact same size as the original?
  5. On Windows: are you running the commands interactively in an open terminal window?

6. Example batch file (Windows – safe version)

@echo off
rage --passphrase -o v1.enc v1.zip
if errorlevel 1 (
    echo Encryption failed
    pause
    exit /b 1
)

rage --decrypt -o v2.zip v1.enc
if errorlevel 1 (
    echo Decryption failed
    pause
    exit /b 1
)

echo Success – v2.zip should now match the original.
pause
